Docker & Konfigurace serveru

Celou backendovou část systému spouštíme v izolovaných kontejnerech platformy Docker. Díky tomu je aplikace zcela nezávislá na hostitelském operačním systému serveru, odpadá nutnost ruční instalace knihoven a závislostí a systém se chová naprosto stejně na lokálním vývojovém počítači i na produkčním serveru. Celé prostředí tak zprovozníte na čistém serveru jediným příkazem.

Požadavky na hardware a software

Před nasazením systému si prosím ověřte, že váš server a koncová zařízení splňují tyto minimální požadavky:

Komponenta Minimální požadavek Doporučení
Server Libovolný Linux server s Docker Engine Ubuntu 22.04+ LTS, 2 GB RAM, 20 GB disk
Docker Docker Engine 20.10+ Nejnovější stabilní verze
Docker Compose Compose V2 (plugin docker compose) Verze 2.20+
TV panel Libovolný televizor s HDMI vstupem Full HD (1920 × 1080) nebo 4K
Kiosk zařízení Raspberry Pi / Android TV box / mini PC Chromium v režimu Kiosk
Mobilní zařízení Android 8.0+ nebo iOS 14+ Zařízení s fotoaparátem a Wi-Fi

Konfigurace parametrů prostředí (soubor .env)

Před prvním spuštěním kontejnerů si v kořenové složce projektu vytvořte konfigurační soubor .env. Jako šablona vám poslouží připravený vzorový soubor .env.example. Do souboru .env doplňte vlastní heslo k databázi a čtyřmístný PIN:

# Konfigurace PostgreSQL databáze
DB_HOST=db
DB_PORT=5432
DB_NAME=postgres
DB_USER=postgres
DB_PASS=silne_uzivatelske_heslo

# Autorizační kód pro mobilní aplikaci
MOBILE_APP_PIN=
warning
Bezpečnostní upozornění: Soubor .env obsahuje heslo k databázi a přístupový PIN pro mobilní aplikaci. Tento soubor je zařazen v .gitignore a nesmí se dostat do veřejného repozitáře. Pokud měníte heslo k databázi po jejím prvním spuštění, je nutné smazat stávající svazek PostgreSQL příkazem docker compose down -v a nechat databázi sestavit znovu.

Topologie služeb v Docker Compose

Běh a propojení celého prostředí řídí konfigurační soubor docker-compose.yml. Ten definuje dvě služby běžící ve společné izolované virtuální síti:

  • db (PostgreSQL 16-alpine): Relační databáze systému. Trvalé uložení dat zajišťuje pojmenovaný svazek pgdata. Soubor init_db.sql se při prvním spuštění automaticky načte (přes inicializační adresář /docker-entrypoint-initdb.d/init.sql), což vytvoří potřebné tabulky a naplní je výchozími daty pro testování. Zdravotní stav databáze průběžně ověřuje healthcheck (pg_isready) každých 10 sekund.
  • web (Flask + Gunicorn): Webový aplikační server naslouchající na portu 5001. Aplikaci pohání robustní WSGI server Gunicorn s vícevláknovými workery (gthread). Lokální složka static/uploads je namontována přímo na disk hostitelského serveru, takže pořízené fotografie zůstanou bezpečně uloženy i při restartu či zničení kontejneru.

Správa a CLI příkazy

Pro spouštění, sledování a správu kontejnerů slouží tyto standardní příkazy spouštěné v kořenové složce projektu (kde se nachází soubor docker-compose.yml):

# Sestavení obrazů a spuštění celého systému na pozadí
docker compose up -d --build

# Zobrazení stavu a healthchecků spuštěných služeb
docker compose ps

# Sledování systémového logu Flask serveru v reálném čase
docker compose logs -f web

# Bezpečné zastavení kontejnerů bez ztráty dat v DB
docker compose down

# Restart webové služby (např. po změně konfigurace)
docker compose restart web

Záloha a obnova databáze

Data v PostgreSQL databázi se ukládají do Docker svazku pgdata. Tento svazek bezpečně přežívá běžná zastavení i restarty kontejnerů (docker compose down). Ke smazání dat by došlo pouze při explicitním smazání svazku parametrem -v.

Příkaz Data v DB Fotky na disku
docker compose down ✅ zachována ✅ zachovány
docker compose restart ✅ zachována ✅ zachovány
docker compose down -v ❌ smazána ✅ zachovány

Před jakýmkoliv čištěním svazků doporučujeme vytvořit aktuální zálohu databáze:

# Export aktuální DB do souboru zálohy
docker compose exec db pg_dump -U postgres postgres > webova_aplikace/zaloha_db.sql

# Úplné vyčištění DB a nová inicializace z init_db.sql
docker compose down -v && docker compose up -d --build
warning
Upozornění: Použití parametru -v při zastavení systému nevratně smaže databázový svazek PostgreSQL. Po novém startu se databáze inicializuje ze souboru init_db.sql a veškeré změny či nově vyfocená jídla od poslední zálohy budou ztraceny.

Řešení častých problémů

Příznak Možná příčina Řešení
Kontejner web se neustále restartuje Databáze ještě neprošla healthcheckem Vyčkat 30 sekund, ověřit docker compose ps
TV panel zobrazuje „Dnes není dostupná žádná nabídka" Všechny porce daného pokrmu jsou vyprodány, nebo API WebKreditu nevrací data (víkend, svátek) Ověřit log: docker compose logs web
Mobilní aplikace hlásí „Databáze nedostupná" Kontejner db neběží nebo chybné údaje v .env Ověřit stav DB: docker compose ps db
Fotky se po restartu nezobrazují Složka static/uploads není namontovaná jako volume Ověřit konfiguraci volumes v docker-compose.yml
