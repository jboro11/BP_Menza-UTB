Synchronizace & Importér (robot.py)

Automatický import a synchronizaci denního menu z univerzitního stravovacího systému WebKredit do naší lokální PostgreSQL databáze zajišťuje skript robot.py. Tento modul hraje klíčovou roli v celém datovém toku: plní databázi novými jídly, řadí je do správných kategorií a doplňuje k nim anglické překlady z API.

Princip fungování a datový tok

Při spuštění synchronizace skript pro každou sledovanou jídelnu provede tyto kroky:

  1. Stažení surových dat – z API WebKreditu stáhne jídelníčky v české i anglické verzi. API vyžaduje přesný časový parametr odpovídající půlnoci pražského času vyjádřené v UTC (např. 2025-11-10T23:00:00.000Z).
  2. Párování jazykových verzí – český název spojí s anglickým překladem na základě složeného klíče jídla (meal_kind_id, alt_id). Tím se vyhneme chybám, pokud API vrátí jídla v odlišném pořadí.
  3. Vytvoření slugu (normalizace) – z českého názvu odstraní diakritiku, mezery a převede text na malá písmena. Tím vznikne unikátní identifikátor (slug, např. 120gkurecirizek), který slouží pro rychlé vyhledávání a zamezení duplicitám.
  4. Uložení do databáze (Upsert) – skript zkontroluje, zda jídlo se stejným slugem již v tabulce meals existuje. Pokud ne, vloží ho jako nový záznam a zařadí pod odpovídající kategorii. Pokud v databázi už je a chybí mu pouze anglický překlad, tak ho doplní.

Časová specifika API WebKreditu

API WebKreditu vyžaduje pro získání jídelníčku specifický časový parametr – přesnou půlnoc světového času (UTC) odpovídající danému dni v pražském časovém pásmu. Jakákoliv odchylka nebo nepřesný čas způsobí, že API vrátí prázdnou sadu dat.

Tuto konverzi automaticky řeší pomocný modul menu_collector.py v metodě ziskej_datum_pro_api(). Ta správně převádí lokální datum na cílový UTC timestamp s ohledem na střídání letního a zimního času (CET/CEST).

schedule
Příklad konverze: Pro získání jídelníčku na pondělí 25. května 2026 je potřeba zadat UTC timestamp 2026-05-24T22:00:00.000Z (půlnoc CEST = 22:00 UTC předchozího dne kvůli letnímu času UTC+2).

Periodické spouštění (Cron job)

V ostrém provozu je nejlepší spouštět synchronizaci jednou denně brzy ráno (např. v 5:00), ještě před začátkem směny v kuchyni. Tím zajistíte, že obsluha bude mít v mobilní aplikaci hned od rána aktuální jídla připravená k focení.

Skript můžete uvnitř běžícího aplikačního kontejneru spustit ručně tímto příkazem:

docker compose exec web python robot.py

Pro automatické spouštění pomocí systémového plánovače cron na vašem Linux serveru přidejte záznam do tabulky úloh:

# Editace crontabu
crontab -e

# Přidání záznamu pro spuštění každý den v 5:00
0 5 * * * cd /cesta/k/projektu && docker compose exec -T web python robot.py >> /var/log/menza_robot.log 2>&1

Sledování logů a diagnostika

Průběh synchronizace (počet nových jídel, spárované překlady a případné chyby) se zapisuje do systémového logu kontejneru a také do lokálního souboru robot.log:

# Sledování výstupu v reálném čase
docker compose logs -f web

# Zobrazení posledních 50 řádků logu
docker compose logs --tail 50 web
lightbulb
Lokální testování modulu: Pro testování nebo jednorázové stažení dat bez nutnosti zápisu do PostgreSQL lze využít přímo CLI rozhraní collectoru: python menu_collector.py --date 2025-11-12 --canteen 2. Výsledná data se uloží v formátech CSV a JSON do složky příslušného stravovacího zařízení.
