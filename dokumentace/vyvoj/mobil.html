Mobilní vnitřnosti (Isolates & Cache)

Mobilní aplikaci jsme vyvinuli ve frameworku Flutter (jazyk Dart) verze 3.x. O správu stavu (State Management) se stará architektonický vzor Provider využívající třídu ChangeNotifier. Tento přístup důsledně odděluje vzhled (UI widgety) od samotné logiky aplikace (MenuProvider), což usnadňuje testování a budoucí údržbu kódu.

Architektura a struktura zdrojového kódu

lib/
├── main.dart               # Vstupní bod aplikace, inicializace Providerů
├── config/
│   └── api_config.dart     # URL adresy API serveru, timeouty
├── models/
│   └── meal.dart           # Datový model pokrmu (Meal)
├── providers/
│   └── menu_provider.dart  # ChangeNotifier se stavem jídelníčku
├── screens/

│   ├── menu_screen.dart    # Seznam pokrmů dle menzy
│   └── photo_screen.dart   # Pořízení, náhled a odeslání snímku

Asynchronní zpracování obrazu na pozadí (Dart Isolates)

Protože běhové prostředí Dartu je jednovláknové (využívá Event Loop), jakékoliv náročné operace na hlavním vlákně by způsobily nepříjemné škubání rozhraní (UI jank). Dekódování surových dat z fotoaparátu, ořez, změna rozlišení na 1200x1200px a aplikace filtrů by na hlavním vlákně zablokovaly aplikaci na 500 až 1500 ms podle výkonu telefonu.

Tento problém jsme vyřešili přesunutím kompletní úpravy fotek do samostatného vlákna na pozadí (Dart Isolate). V modulu image_editing_service.dart k tomu využíváme metodu compute:

// Delegování výpočetně náročné filtrace do samostatného Isolátu
Future<Map<String, Uint8List>> getPreviewBytes({required String imagePath}) async {
  return compute(_processImageInIsolate, imagePath);
}

Isoláty nesdílejí paměť s hlavním vláknem a komunikují výhradně posíláním zpráv přes porty. Do isolátu předáme cestu k obrázku, na pozadí proběhne zpracování (ořez, zmenšení, normalizace jasu, saturace a doostření) a výsledné pole bajtů (pro původní i upravenou verzi) se pošle zpět hlavnímu vláknu pro okamžité vykreslení.

speed
Výkonový přínos: Díky přesunu výpočtů do isolátu zůstává hlavní vlákno zcela volné pro animace a reakce na dotyky uživatele. Zpracování snímku na pozadí trvá obvykle 300 až 800 ms, během nichž aplikace zobrazuje plynulé načítání bez jakéhokoliv zaseknutí.

Zamezení texture loading flash (IndexedStack)

Při běžném podmíněném vykreslování obrázků (if-else) by při přepínání původní a upravené verze docházelo k opětovnému načítání a dekódování textury do GPU paměti. To by se na displeji projevovalo jako rušivé šedé či černé probliknutí trvající 50 až 150 ms.

Abychom toto problikávání zcela odstranili, použili jsme widget IndexedStack:

IndexedStack(
  index: _showOriginal ? 0 : 1,
  children: [
    Image.memory(widget.originalBytes, fit: BoxFit.contain),
    Image.memory(widget.filteredBytes, fit: BoxFit.contain),
  ],
)

IndexedStack drží obě verze snímku přednačtené v GPU paměti současně, přestože vidět je vždy jen jedna z nich. Přechod mezi nimi (při podržení prstu přes GestureDetector) je díky tomu naprosto okamžitý, plynulý a bez jakýchkoliv grafických vad. Mírně vyšší paměťová náročnost je v tomto případě zcela zanedbatelná.

Struktura perzistentní offline fronty

Pokud odeslání fotky selže kvůli síti (např. SocketException nebo TimeoutException), spustí se mechanismus offline fronty, který spravuje třída UploadQueueService (navržená jako Singleton). Informace o čekajících úlohách se uloží do souboru JSON na lokální disk telefonu:

// Perzistentní fronta v souboru queue.json
[
  {
    "id": "1716503923481",
    "mealId": 348,
    "mealName": "Kuřecí prsa na bylinkách",
    "imagePath": "/data/.../upload_queue/queue_img_348.jpg",
    "timestamp": "2026-05-24T02:18:43.000"
  }
]

Samotný obrázek se zkopíruje z dočasné složky fotoaparátu do trvalého adresáře aplikace (getApplicationDocumentsDirectory()), takže v telefonu zůstane i po restartu zařízení nebo úplném zavření aplikace. Po úspěšném dodatečném odeslání na server se lokální soubor smaže, aby zbytečně nezabíral místo v telefonu.

Komunikace se serverem (HTTP klient)

Veškerou komunikaci se serverem sdružuje modul api_service.dart. Zajišťuje tyto operace:

Operace HTTP metoda Endpoint Formát dat
Ověření PINu POST /api/mobile/verify_pin JSON ({"pin": "VÁŠ_PIN"})
Stažení jídelníčku GET /api/mobile/menu JSON (pole pokrmů)
Nahrání fotografie POST /api/mobile/upload multipart/form-data

Každý HTTP požadavek má nastavený časový limit (timeout 15 sekund), aby aplikace nečekala nekonečně dlouho při výpadku serveru. V případě jakékoliv chyby se uživateli zobrazí srozumitelná zpráva přes SnackBar widget.
